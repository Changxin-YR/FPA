# 这个目录**是空的，而且是有意的**

## 为什么留着一个空目录

`docs/DECISIONS.md` Q21（推翻「`materials` 保留只读」）里论证过一件事：

> 原裁决说物料"由**种子或导入**建立"。核实方式（三条命令，任何人可复跑）：
> `database/seeds/` 下没有任何种子；全仓唯一建立物料的路径是 003 迁移末尾那条
> `INSERT INTO materials ... SELECT ... FROM areas CROSS JOIN (...)`（只种 2 条演示饲料）；
> `tools/` 下也没有任何导入器。
> 结论：**"由种子或导入建立"在本版没有任何可执行路径** —— 原裁决描述的那条路不存在。

那个论证的前提就是这个目录当时是空的。**留着它（而不是删掉）是为了让那句话可被复核**：
下一个人跑 `Get-ChildItem database\seeds` 会看到空目录，而不是"目录不存在"。

## 种子数据现在在哪

* **结构化种子**：写在迁移文件里 —— `database/migrations/001`–`009` 的末尾都有"种子"段
  （演示账号、农场/区域/塘口、2 条演示饲料、默认仓库…）。这是**唯一**的种子入口。
* **权限码**：**不手写**，由 `python tools\seed_permissions.py` 从能力注册表**派生**
  （手抄清单必然漂移，见该脚本的 docstring）。
* **演示角色**：`tools/seed_permissions.py --demo-role`（验收专用；生产库应摘掉）。

## 什么时候该往这里放东西

当真出现"**运行期可重复执行、且与迁移无关**"的数据装载需求时（例如从外部系统导入物料主数据）。
在那之前，**保持空**比放一个手写清单更好 —— 后者会变成第二处真相。
